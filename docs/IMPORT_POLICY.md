# Правила импорта и раскладка репозитория

Этот файл фиксирует, откуда в проекте берутся внешние данные и файлы.
Папка `vendor/` в git не попадает (см. `vendor/.gitignore`): в ней живут
только локальные копии импортированных проектов.

## Раскладка

```
ProjectAuroraWoW/
├── src/            AuroraCore — слой кастомизации
├── modules/        модули AzerothCore (24 шт.)
├── databases/      SQL-схемы Aurora
├── docs/           документация; docs/imported/ — разбор импортов
├── tools/          конвертеры и утилиты (adt2json, генераторы)
├── tests/          проверки без запуска сервера
├── ue/             UE 5.8-клиент
├── web/            PHP-панель
├── vendor/         локальные копии чужих проектов (в git не входит)
└── externals/      WoW-клиент (в git не входит)
```

## Категории внешних файлов

| Категория | Куда | В git | Пример |
|---|---|---|---|
| Код чужого проекта с явной лицензией | `vendor/<name>/` | нет | модуль, лицензия MIT |
| Код без лицензии | не берём | — | `waloriaold/scripts` |
| Игровые данные Blizzard (ADT, MPQ, DBC) | `externals/` или локально | нет | `custom-maps` |
| Контент, сгенерированный из данных Blizzard | `assets/` с `license` в манифесте | по решению | JSON-чанки из `adt2json` |
| Бинарники без исходников | не берём | — | `waloria.exe` |

## Почему `vendor/` вне git

Копии чужих проектов нельзя распространять повторно без их собственной
лицензии. Держать их в рабочем дереве удобно для справки, но коммитить —
значит смешивать чужой код с нашим под GPLv3. Поэтому `vendor/`
исключён, а в `docs/imported/REVIEW.md` фиксируется, что именно мы
оттуда взяли на уровне идей.

## Проверка лицензий

Для данных, которые всё-таки попадают в репозиторий, действует то же
правило, что и в UE-клиенте: `FExternalAssetSource` читает поле
`license` из `manifest.json` и пропускает только `cc0`, `cc-by`,
`cc-by-sa`, `proprietary-own`, `user-owned`. Конвертер `tools/adt2json`
принимает только эти значения и падает на любых других.

## Что делать с новым импортом

1. Положить проект в `vendor/<name>/`, не в `modules/`.
2. Прочитать его README и найти лицензию.
3. Если лицензии нет — описать проект в `docs/imported/REVIEW.md` и не
   брать код.
4. Если лицензия есть — записать её тип в `REVIEW.md` и указать, какие
   именно идеи/файлы перенесены.
