# adt2json

Конвертер карт WoW 3.3.5a (ADT/WDT) в JSON-чанки для
`FExternalAssetSource` в UE-клиенте Aurora.

## Зачем

Источник `FExternalAssetSource` (вариант 2 этапа 5) читает чанки террейна
из JSON и загружает их только при наличии допустимой лицензии в
`manifest.json`. Конвертер — единственное звено между бинарными картами и
этим источником.

## Использование

```bash
python tools/adt2json/adt2json.py \
    --input "C:/Users/Orel/Downloads/СД/.../World/Maps/CustomMaps" \
    --output ./assets/custom_maps \
    --map CustomMaps \
    --license user-owned
```

`--license` обязателен, и допустимы только значения, которые принимает
`ExternalAssetPolicy`: `cc0`, `cc-by`, `cc-by-sa`, `proprietary-own`,
`user-owned`. Любое другое значение конвертер отклоняет: это не формальность,
а механизм, который не даёт затащить чужие ассеты в публичный репозиторий.

## Формат вывода

```
assets/custom_maps/
├── manifest.json
├── terrain/CustomMaps_25_57.json
├── terrain/CustomMaps_26_57.json
└── ...
```

Каждый чанк:

```json
{
  "rows": 129,
  "cols": 129,
  "vertices": [
    { "x": -13950.0, "y": 2877.0, "z": 9.0 },
    ...
  ]
}
```

## Ограничения

- Читается только высотная сетка (MCNK → MCVT) и базовая позиция тайла.
  Текстуры, вода, WMO и M2 не переносятся.
- Формат ADT у WotLK — `MVER`, `MHDR`, `MCIN`, `MTEX`, `MMDX`, `MCNK`.
  Конвертер ориентируется на этот порядок; для других версий он откажется
  работать вместо того, чтобы выдать мусор.
- Сетка 129×129 на тайл — стандарт 3.3.5a. Если в файле другое число
  высот, конвертер пишет предупреждение и берёт ровно 129×129.

## Почему не тащим сами ADT в git

ADT — производная работа от клиента Blizzard. Внутри проекта они
допустимы как локальные данные для своего сервера, но в публичный
репозиторий их класть нельзя. Конвертер этого и не требует: он читает
файлы на машине пользователя.
